4.4.4. Recursión vs Bucles

Coste de la recursión

Como ya hemos visto, por cada llamada recursiva:

  1. Se crea un nuevo escalón en la pila de llamadas.
  2. Se guardan y actualizan variables locales.
  3. Guardamos la dirección de retorno para devolver el valor que nos hayan pedido.

Esto implica más uso de memoria, más trabajo interno (tiempo) y además puede provocar stack overflow si hay demasiadas llamadas. Por eso, los bucles son más eficientes en tiempo y memoria.

¿Qué es un StackOverflow?

En Java (y en casi cualquier lenguaje), un StackOverflowError ocurre cuando la pila de llamadas (call stack) se llena y ya no queda espacio para seguir guardando más información.

¿Cuándo ocurre un StackOverflow?

Principalmente cuando hay demasiadas llamadas anidadas, normalmente por recursión mal controlada. Por ejemplo, este código crea llamadas y llamadas sin parar hasta que la pila se queda sin espacio:

void rec() { rec(); } // llamada infinita
Entonces… ¿por qué usar recursión?

Algunos algoritmos son naturalmente recursivos (DFS, quicksort, mergesort) y el código queda más claro (árboles, grafos, divide‑y‑vencerás) pero incluso ahí, muchas implementaciones optimizadas usan bucles internos.

Otro uso común es el backtracking que habéis usado algunos de vosotros para resolver sudokus, laberintos, etc. en problemas típicos de olimpiada. En esos casos, la recursión hace que el código sea más claro y más fácil de razonar.

Ejercicio: medir tiempo y memoria

Código base para medir tiempo y memoria:

System.gc(); //Limpia lo que pueda antes de medir

long inicioEjecucion = System.nanoTime();
long memoriaAntes = Runtime.getRuntime().totalMemory() - Runtime.getRuntime().freeMemory();

// PROGRAMA A REALIZAR

long finEjecucion = System.nanoTime();
long memoriaDespues = Runtime.getRuntime().totalMemory() - Runtime.getRuntime().freeMemory();

System.out.println("Tiempo: " + (finEjecucion - inicioEjecucion) + " ns");
System.out.println("Memoria consumida: " + (memoriaDespues - memoriaAntes) + " bytes");

System.gc()

gc() en Java sirve para sugerir que se limpie memoria que ya no se está usando. La palabra clave aquí es sugerir: no obliga a nada, no garantiza que ocurra en ese momento y la JVM puede ignorarlo si quiere. Esto es así porque en Java moderno, la JVM gestiona la memoria mejor que cualquier llamada manual.

No deberíamos usarlo en entornos de producción salvo en casos muy específicos.

b) Mide el tiempo y la memoria usada por cada uno de los métodos y compara los resultados obtenidos para ambos.

b) Fuerza un error StackOverFlow del método recursivo dando un valor 100.000 a N:

Comprueba que el método no recursivo, en cambio, funciona perfectamente.
