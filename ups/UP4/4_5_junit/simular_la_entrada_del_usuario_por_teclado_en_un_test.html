Simular la entrada del usuario por teclado en un test

Supongamos que tenemos un método que pide un número entero:

public class LeerTeclado {

    public static int leerEntero() {
        Scanner teclado = new Scanner(System.in);
        System.out.print("Introduce un número: ");

        try {
            return teclado.nextInt();
        } catch (InputMismatchException e) {
            System.out.println("Formato de entrada no válido (número entero).");
            return -1; //definimos un valor predeterminado en caso de error
        }
    }
}

Si necesitamos introducir datos para testearlo, la estructura de nuestra clase @Test quedaría así:

class LeerTecladoTest {

    @Test
    void testEntradaSimulada() {

        // simulamos que el usuario escribe "42"
        String entradaSimulada = "42";
        System.setIn(new ByteArrayInputStream(entradaSimulada.getBytes()));

        // llamamos al método, que ahora leerá del input simulado
        int resultado = LeerTeclado.leerEntero();

        // comprobamos que devuelve lo esperado
        assertEquals(42, resultado);
    }

}

¿Cómo simula el test la entrada del usuario?

El test crea un input falso:

String entradaSimulada = "aaa";
System.setIn(new ByteArrayInputStream(entradaSimulada.getBytes()));

Esto significa que en lugar de leer del teclado real, System.in ahora leerá "aaa" desde un flujo de bytes.

Vale pero... ¡¿por qué System.setIn() se pone antes de llamar al método?!

Porque el método que se está probando crea el Scanner así:

Scanner teclado = new Scanner(System.in);

y Scanner lee del System.in en ese mismo momento. Por lo tanto:

  • Si antes de crear el Scanner hacemos System.setIn(...), el Scanner leerá el input simulado.
  • Si lo hacemos después, ya es tarde: el Scanner se ha quedado conectado esperando al teclado real y entraremos en bucle. Pruébalo.
